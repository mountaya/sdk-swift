# Contributing

The commands to build and test, and the rules a change follows, are in `AGENTS.md`.

The gate, `mise run ci`, starts with `mise run clean`, which deletes build output inside this
repository and nothing else. The Linux images its containers run, `swift:<version>-noble`, live in
Docker's disk, which every project on the machine shares: `mise run clean:toolchains` lists those of
a Swift no Mountaya checkout pins any more, and deletes them only with
`mise run clean:toolchains -- --yes`. It is yours to run, and an agent is denied it. The device
suites run on the iOS simulator with `mise run test:device`, and after a deliberate change to the
public API, `mise run api:update` prints the products' baselines again, whose diff is the review.

## Working with an AI agent

Any coding agent is welcome here. `AGENTS.md` is the entry point for all of them: read it, or have your agent read it, before the first change.

| Agent | What it picks up from this repository |
| --- | --- |
| Claude Code | `CLAUDE.md`, which imports `AGENTS.md`; `.claude/settings.json` (model, permissions, plugins, MCP servers); rules and skills under `.claude/` |
| Codex | `AGENTS.md`, `.agents/skills/` |
| Cursor | `AGENTS.md` |
| Any other | `AGENTS.md` and `.agents/` |

**Getting the code.** Every Mountaya repository lives on Entire. Install the Entire CLI and log in once per machine, clone this repository, and let `.agents/setup` do the rest. It clones what this repository builds against beside it, `mountaya/ai` included, installs the git hooks, turns Entire's recording on for every agent, gives your agents the shared conventions, sets Brain up and installs the toolchain. It asks before each step and does only what is missing, so it is also what to run to update; `--check` reports without changing anything.

```bash
brew install --cask entireio/tap/entire && entire login   # once per machine (Linux: curl -fsSL https://entire.com/install.sh | bash)
entire repo clone /et/mountaya/sdk-swift
cd sdk-swift && sh .agents/setup
```

**CI runs on Depot.** Every push to Entire runs `mise run ci:linux`, part of the gate, on Depot CI, and its job shows as a check on the commit in Entire. Run `depot login` once, and `depot ci run list` and `depot ci logs <run>` read its runs from your terminal; `depot ci run --workflow .depot/workflows/ci.yml` runs it on your uncommitted changes, without a push. The whole gate, `mise run ci` (tests and the build), runs only where you work: run it before you push. CI builds against the commits of the repositories beside this one that `siblings.lock` pins, fetched as the bundles each sibling's own CI publishes on every push. `pre-commit` keeps the lock on what you tested: it stops while any sibling checked out beside this one has uncommitted or untracked files or a commit not yet pushed (any branch will do), naming each one, then pins each sibling whose HEAD moved forward and stages `siblings.lock`, and stops on a HEAD behind or diverged from its pin. A commit that changes `siblings.lock` itself, such as a rollback, or concludes a merge keeps the pins it sets, and `SIBLINGS_ALLOW_DRIFT=<name> git commit` leaves a pin where it is, never past uncommitted or unpushed work. `pre-push` stops a push whose commit carries no `siblings.lock`, or whose pin no remote branch holds or its sibling's CI never ran on, and `sh .agents/siblings status` shows where each pin stands. A release runs `sh .agents/siblings at-pins` before it commits and tags, which stops unless every sibling is checked out, clean and at its pin, so the release commit never moves a pin. A pin may name an unreleased commit on any branch. A push of `main` or of a release tag also reaches the read-only public mirror on GitHub, https://github.com/mountaya/sdk-swift, from Depot CI: the mirror takes no change of its own, so clone, push and open trails here. `pre-commit` runs `mise run ci:quick`: formatting and linting, and `git commit --no-verify` skips it.

**Review happens on trails.** Push a branch and open a trail with `entire trail create --branch <branch>`; `entire review` runs a multi-agent review of the branch first, if you want one. Merge on entire.com or by merging into `main` and pushing it. CI runs only part of the gate either way, so run `mise run ci` on what you merge before you merge it.

**Rules every agent follows here.**

- Git is read-only for an agent: it reads diffs, logs and status, and a person commits and pushes.
- Entire's repository, trail, login and setup commands are yours. An agent reads trails, checkpoints and Brain, answers trail findings and records facts with `entire brain remember`; it suggests everything else.
- `.claude/settings.json`, `.githooks/`, `.depot/workflows/ci.yml`, `.depot/workflows/mirror.yml`, `.agents/siblings` and `.agents/setup` are rendered from `.agents/manifest.json`. Change the manifest and run `node ../ai/scripts/apply.mjs`, never the files themselves.
- Personal settings go in `.claude/settings.local.json`, which is never committed.

**Recorded sessions.** Entire records your agent sessions as checkpoints on your machine. Until the first release they are not pushed (`push_sessions: false`), so nothing recorded before it reaches a remote; after it, they will be pushed with your commits, where everyone who can read this repository can read them.
